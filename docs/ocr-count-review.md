# テスト依頼の0件と問題数の読み落とし

- テスト作成依頼の行内では「問」を「題」と認識した数字も問題数として受け付けます。
- OCRが複数セルを同じ行として返す場合、横方向の大きな隙間を使ってセルを区別します。
- 教材の科目見出しがあるのに問題数を読めない列は、問題数未確認（画面では空欄）の候補として残します。問題数が意図的に空欄だった列も含まれるため、依頼なしなら作成チェックを外してください。
- 未確認の問題数は推測せず、入力・除外するまでPDF作成不可とします。教材名や範囲の誤認識も原本との照合が必要です。
- 依頼欄があるのに候補が0件の場合、要確認表示・読み取り後の警告・要確認フィルター・エラーCSVへ反映します。自動的に「依頼なし」とは扱いません。

2026-05-28のレポートは、Windows OCRで0件から5候補へ改善したことを確認しました。SUPREMACYは教材名末尾・範囲・問題数の読み取りが不完全なため、未確認として残しています。これは完全自動化成功という意味ではありません。

アプリ本体のビルド、147件の回帰テスト、未確認問題数の入力制御、0件警告の要確認フィルターへの反映を検証しました。原本の変更や実印刷はしていません。
